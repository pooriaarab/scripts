# paper-publish failure modes

`paper-publish` helps a person publish a paper fast. It makes a Zenodo draft, saves repos to Software Heritage, writes one submission packet per venue, and checks a paper before anyone submits. It never submits to a peer-reviewed venue. It never publishes a Zenodo record unless a person passes two flags.

The tests in `paper-publish.test.sh` run against a fake local server. They use no network and no real token. They cover each row marked "yes". The `meta.json` keys are `title` and `abstract` (strings), `authors` (a list of objects with `name`, `affiliation`, `orcid`), `license`, `keywords`, `subject_class`, `comments`, `code_url`, `data_url`, `data_concept_dois`, `related_identifiers`, and `venues` (a list of venue names). Each name in `venues` must match one venue in `paper-venues.json`. `packet` writes one file for each.

| # | Failure | Wanted behavior | Tested |
|---|---|---|---|
| 1 | `ZENODO_TOKEN` is not set. | Exit 2. Send no request. | yes |
| 2 | The token has a space, a control character such as a trailing `\r`, or a non-ASCII character. Or any other unexpected error. | Exit 2 at start and never show the value. For any other unexpected error: exit 1, pass the message through the token scrub, print no traceback. Scrub a response body whole before the 200-character cut, so a token split by the cut cannot show a prefix. Scrub the printed draft id, concept id, preview URL and DOI too. Scrub the token and its JSON-escaped forms (`\"`, `\\`, `\/`), its `\uXXXX` form (lower and upper case hex) and its URL-encoded form. Scrub the whole body, read 4096 bytes past the 1 MiB cap, before the cut, so the cap cannot split a token. Cut the printed text so that it never ends with the start of the token. If the token is split across the string values of a response (for example `message` and `errors`), hide the whole response. Decode a response with json and scrub every string and key, then scrub the raw text, so the token is hidden when the body is not a JSON object, when it is written with escapes, when a message holds JSON text, and when the concept id is an object that holds it. A body that is not JSON or is nested too deep, and a `message` that is not a string, give `HTTP n:` and the text, never `unexpected problem`. | yes |
| 3 | A person passes the token in argv, for example `--token X`. Or abbreviates a flag, for example `--pub`. | Exit 2. No such option exists. Abbreviations are off, so `--pub --i-confirm-permanent` cannot pass the publish gate. An argument error never repeats a value. | yes |
| 4 | An upstream error body repeats the Authorization header. An upstream redirects to another host. A response body links to another host or to another port. The base URL is plain http on a host that is not localhost. | Replace the token with `***`. Drop the header on a cross-host redirect. Refuse any link (bucket, latest_draft, self) whose scheme, host or port differs from `ZENODO_BASE`, with exit 2. The host compare ignores case, and an explicit default port equals none. Refuse an http base unless the host is localhost, 127.0.0.1 or ::1. The tests use the bucket link and the base check. | yes |
| 5 | `--publish` without `--i-confirm-permanent`. | Print the exact title and file list. Exit 2. Send no request, not even the draft call. | yes |
| 6 | `--publish` with both flags. | Build the draft. Then send one publish call. | yes |
| 7 | A plain run. | Stop at a draft. The upstream never sees a publish call. Print the draft id and the preview URL. | yes |
| 8 | Zenodo answers 4xx, 5xx, a non-JSON body, or any status other than the one expected: 200 for lookups and metadata, 201 for create and new version, 200 or 201 for upload, 204 for delete, 202 for publish. | Exit 1. Name the step, the status, and the message. If the draft exists, name its id so a person can discard it, for every failure after the draft is made: the new-version draft fetch, a missing `links` or `html`, and a failed publish call (then say to check whether it was published). Do not retry. | yes, except a 3xx |
| 9 | A file is missing, or larger than the 50 GB Zenodo limit. | Exit 2 before any request. Name the file. | yes |
| 10 | `--new-version-of` names a concept id. | `GET /records/<concept>/versions/latest`, then `POST .../actions/newversion`, then fetch `links.latest_draft`. Remove the inherited files. Upload the new files. | yes |
| 11 | The server is unreachable. Or `meta.json` is not JSON (a UTF-8 BOM is accepted), has a wrong type (a venue list, `related_identifiers` or `data_concept_dois` that is a string or null, authors that are strings, a title that is a number), is a top-level array, is nested so deep that JSON gives up, or lacks title, abstract, authors, or license. | Exit 1 with `cannot reach` and the host, or exit 2 and give a reason. No traceback. | yes |
| 12 | Software Heritage answers 429, with a `Retry-After` that is missing, negative, or huge. | Wait for the `Retry-After` seconds, at most 60. Use 60 if the value is not a number. Use 0 if it is negative, nan or inf. Retry the same call. A negative, nan or inf `--interval` or `--timeout` exits 2, because nan never ends. | yes, except the cap and a negative value |
| 13 | A save request fails, is rejected, times out, or the answer has no request id or is not JSON. Or a URL is not http or https, or has a newline in it. A poll answer that is a list of non-objects counts as no answer, and the run goes on. | Print the status for that URL and go on. Exit 1 at the end. Refuse a bad URL with exit 2 before any request. Percent-encode the origin URL in the call. | yes, except the encoding |
| 14 | `packet` names a venue that `paper-venues.json` does not list, or a name that matches several venues, for example `IEEE`. Or the same venue twice, even under two names such as `arXiv` and `arXiv (cs.AI, cs.CL, cs.LG)`, or `Zenodo` and `Zenodo (paper copy)`, or a shortlist row and the typed row it points at. A note row, and a group row, are refused. A shortlist or pointer row with no type resolves to the one typed row it names (by its name before a bracket, its `best fit` or an acronym in its `need`), so the typed row decides and the duplicate check sees one venue. Or a note row such as `How a community works`, or a group row that names several venues, for example `All ACM journals ...`. | Exit 2. Write no file. Do not invent a venue. Take an exact name first, else a unique prefix. If several venues match, list the candidate names. A venue listed twice, under any names, exits 2 and names it. | yes |
| 15 | `packet` names two peer-reviewed venues, or one that is and one that may be. A venue counts from its own words in `paper-venues.json`. Words that deny peer review (not, no, non, without, un-, or `Peer review: none`) make it not peer-reviewed. A `type` that starts with journal, conference, workshop, track, challenge track, route into main track or review pool counts. A `type` with practitioner, blog, forum, newsletter, platform, outlet, news, volunteer, company or commercial, or a magazine that is not a society or flagship magazine, does not count even when it says peer-reviewed (InfoQ). Otherwise peer review, refereed, outside or external reviewers or referees in the type, review or review model counts. Peer Community In counts. A row with no `type` takes the verdict of the typed rows it names (the name before a bracket, or an acronym in brackets in `need`) when they agree. Else a free-venues archive section is not peer review and its journal section is. Else its own words decide. If it is still unknown, the tool refuses, because it cannot tell: pass `--allow-second-review-venue` or name a typed venue. The test prints the verdict of every venue, and of every row with no `type`, into the transcript. | Exit 2 and explain dual submission, or say it cannot tell. `--allow-second-review-venue` lifts it. The checklist then carries a warning. | yes |
| 16 | A venue reviews blind and a person pastes the packet as is. | Each packet shows the venue's review mode and says to hide the authors and use anonymous links when it is blind. | yes |
| 17 | An ORCID has a wrong checksum or shape. | Exit 2 in `zenodo-draft` before any request. `check` lists it as a problem and exits 1. No traceback. | yes |
| 18 | The title differs in `meta.json`, on PDF page 1, or in `CITATION.cff`. | Exit 1. Find the title block of PDF page 1 with `pdftotext -bbox-layout`. Skip every line that is taller than it is wide (a y-axis label, an arXiv side stamp). Take the tallest remaining line (height is yMax minus yMin), then the consecutive lines, from the first such line in reading order, whose height is within 10% of it. A subtitle is the next line or lines if each is 60% to 90% of the title height and its top is closer to the line above than half its own height. If there is a subtitle, the meta title must equal the block plus the subtitle, joined with a space or with a colon and a space. A meta title that is only the block fails then. The normalised text must EQUAL the normalised meta title. Normalising is NFKC, dash and quote variants unified, then every hyphen and space removed. So a prefix, a longer line, an author line, `Abstract`, the title plus a name, and an abstract sentence all fail. A trailing `*`, `∗`, `⋆`, dagger, double dagger, section sign, pilcrow or `‖` is dropped from the block. A trailing digit is dropped only when it is a separate word that is less than 85% as tall as the other words on its line, which is a superscript, so `Web3` and `Llama 3` are never changed. If the bbox data cannot tell, the text must match as it is. A block that is all upper-case is compared to the upper-case title. Otherwise the case must match. | yes |
| 19 | The PDF has no text layout, or `pdftotext` is not installed. | Exit 1 with `cannot find the title block`, with no looser match. Or exit 2 and name the tool. | yes |
| 20 | The `CITATION.cff` title is read wrongly. | If `preferred-citation` has a `title:`, that title is compared, since the top-level title may name the software. Else only the top-level `title:` counts, not a nested one. Quoted (single quotes with `''`, double quotes with `\\"`), plain with a `# comment`, plain and continued on an indented line, folded (`>`, `>-`), and literal (`\|`) titles and a BOM are read. A `CITATION.cff` that cannot be read exits 2 with the reason. The compare keeps the case and collapses white space. A different case fails. | yes |
| 21 | The text has `XXXX`, an em dash (arXiv accepts one, but the house rule is none, so it is a problem), an abstract outside 100 to 1920 characters, a missing title or license, or a bad ORCID. | Exit 1. List every problem, not just the first. | yes |
| 22 | A URL in the abstract, comments, `code_url` or `data_url` is dead or malformed. Or `--offline` is set. | Report the URL as a problem and go on. Send HEAD first, then GET if HEAD does not answer 200, and read at most 1 byte. `--offline` skips the URLs and runs every other check. | yes |
| 23 | Zenodo changes its API. | UNVERIFIED against a live deposit. The calls follow developers.zenodo.org. Only the read call `GET /records/<concept>/versions/latest` ran live, on 2026-10-16. Dry-run on `https://sandbox.zenodo.org/api` first. | no, needs a live token |
| 24 | A person trusts the packet and skips the venue page. Or asks the tool to click Submit, solve a CAPTCHA, or tick an agreement. | Every packet names its source and check date. There is no submit command. `CHECKLIST.md` lists those steps for a person. | no, a human rule |
